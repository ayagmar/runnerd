`~/.config/runnerd/runnerd.toml` names the repositories to serve, the profile each runs on, the shared caches and the systemd slice whose `MemoryMax` is the budget.

## An example

Two runners each for two repositories in a slice with `MemoryMax=33G`; 2 × 9G + 2 × 7G + 512M for the mirror is 32.5G ([`examples/runnerd.toml`](https://github.com/ayagmar/runnerd/blob/main/examples/runnerd.toml) is a complete one):

```toml
[host]
slice = "runnerd.slice"
isolation = "sysbox"

[caches]
mirror = { enabled = true, memory = "512M", cpus = 1, ttl = "168h", max_size = "10G" }
pnpm = { max_size = "5G" }
maven = { max_size = "5G" }

[profiles.jvm]
image = "ghcr.io/ayagmar/runnerd-runner:jvm-0.0.26"
cpus = 8
memory = "9G"
slots = 2

[profiles.node]
image = "ghcr.io/ayagmar/runnerd-runner:node-0.0.26"
cpus = 8
memory = "7G"
slots = 2

[[repositories]]
name = "halyard/ledger"
profile = "jvm"
labels = ["self-hosted", "linux", "x64", "jvm"]

[[repositories]]
name = "halyard/storefront"
profile = "node"
labels = ["self-hosted", "linux", "x64", "node"]
```

## Split light and heavy jobs

A runner may take any queued job of its repository whose labels it has, so it is sized for the heaviest: a 300M linter beside a 6G build waits like the build.

Serve the repository in a smaller second profile with another `[[repositories]]` entry: same `name`, its own `profile` and label. Added to [the example](#an-example):

```toml
[host]
admission = "measured"   # the check then holds the largest runner and the mirror (9.5G) to MemoryMax

[profiles.small]
image = "ghcr.io/ayagmar/runnerd-runner:node-0.0.26"
cpus = 2
memory = "1G"
slots = 4

[[repositories]]
name = "halyard/storefront"
profile = "small"
labels = ["storefront-small"]
```

Then set `runs-on: storefront-small` on the light jobs. A job runs in the pool that has every label in its `runs-on`; `small` leaves out `self-hosted` so unmoved jobs stay on `node`. Each pool has its own slots, `warm` and `build_cache`. The check refuses two pools of a repository that share a label or profile, or whose `build_cache_writers` differ.

## Runner images

[`image/Dockerfile`](https://github.com/ayagmar/runnerd/tree/main/image) has four published stages: `base` (runner, Docker Engine, GitHub CLI), `android` (the Android SDK and JDK 17), `jvm` (nothing yet over `android`) and `node` (pipx, Playwright's libraries). Runner images are linux/amd64 only; binaries ship for x86_64 and aarch64, and on aarch64 the base stage is built on the host with `image_stage`.

A profile sets `image = "ghcr.io/ayagmar/runnerd-runner:jvm-0.0.26"`, pulled before its first runner (keep the tag at the daemon's version; `runnerd doctor` warns when they differ), or `image_stage = "jvm"`, which runs `runnerd-runner:jvm` built from a clone with `docker build --target jvm -t runnerd-runner:jvm image` and never pulls.

runnerd removes published images that no profile names ([ADR 0040](https://github.com/ayagmar/runnerd/blob/main/docs/adr/0040-unused-runner-images-removed.md)).

### Your own image

For system packages the stages lack, build on `base` or `android`:

```dockerfile
FROM ghcr.io/ayagmar/runnerd-runner:base-0.0.26
RUN apt-get update \
    && apt-get install -y --no-install-recommends libpq-dev protobuf-compiler \
    && rm -rf /var/lib/apt/lists/*
```

Build it, set `image = "quillstack-runner:0.0.26"` on a profile, and keep its entrypoint and root user. runnerd pulls an `image` only when Docker lacks it, so build yours first and rebuild from each new `base`; `runnerd doctor` warns when its inherited `runnerd.version` label is not the daemon's.

## Records of failed jobs

`record_failures = true` on a profile keeps each failed job's runner for `runnerctl shell <job>` ([Running](../running/#records-of-failed-jobs)). [`[records]`](#records) bounds them.

## The budget check

<Budget />

`runnerd check-config [file]` reads the slice's `MemoryMax` from systemd, or takes `--memory-max`, and fails when `slots × memory` over all profiles plus the mirror does not fit:

```text
$ runnerd check-config runnerd.toml
runnerd.toml: valid, memory caps sum to 32.5G
$ runnerd check-config runnerd.toml --memory-max 24G
error: slots × memory over all profiles plus the mirror is 32.5G, the slice runnerd.slice's MemoryMax is 24G; lower `slots` or `memory`, or raise the slice's MemoryMax (`runnerd doctor` prints its unit)
```

A slice without a unit file has no `MemoryMax`; the check then warns. Under [measured admission](../admission/#measured-admission) it holds one runner of each profile with the mirror to `MemoryMax` instead, refusing a slice without one.

## Isolation

`sysbox`, which `runnerd init` writes, gives each runner container its own unprivileged Docker Engine. `unsafe-dind` runs privileged containers, so a job can take over the host, and the check refuses it unless `[host]` sets `allow_unsafe = true`. Never serve public repositories: anyone who can open a pull request could run code on your machine. `runnerd doctor` warns for one.

## Caches are shared between repositories

A slot's `~/.cache`, tool cache, Docker images and cache mounts serve the next job in the slot whichever repository it belongs to, and reach the profile's other slots through its snapshot. The pnpm store and Maven repository are shared by all profiles. A job that writes there can leave a package or tool that another repository's later job runs. runnerd removes only the credential files it knows of ([Warm caches](../running/#warm-caches)). Keep repositories that must not trust each other on different profiles, and on different machines if they must not share the pnpm store or Maven repository.

## Every key

A key without a default must be set. Sizes take `K`, `M`, `G` or `T`, durations a number and `s`, `m`, `h`, `d` or `w`. The check refuses 0 for a profile's `cpus`, `memory` and `slots`, an enabled mirror's `memory` and `cpus`, an enabled build cache's `max_size`, `poll_interval`, `records.max_total` and `max_count`, and the `[sizing]` counts and intervals. A saved config applies without a restart, except `[web]`, `history.database` and `caches.build.directory`; changing `host.slice` is refused.

### `[host]`

- `slice`: the systemd slice runners run in; its `MemoryMax` is the [budget](#the-budget-check)
- `isolation`: `"sysbox"`, or `"unsafe-dind"` with `allow_unsafe = true` ([Isolation](#isolation))
- `poll_interval` (default `"15s"`): how often GitHub is asked for queued jobs
- `admission` (default `"caps"`): a runner reserves its profile's `memory`, or with `"measured"` its job's predicted peak ([Admission](../admission/#measured-admission))
- `cpu_overcommit` (default unset): a factor above 0, at most 16; a runner must also fit the slice's CPUs times it ([CPU admission](../admission/#cpu-admission))
- `memory_ceiling` (default unset): for a VM whose memory grows on demand, the most it grows to ([A host whose memory grows](../admission/#a-host-whose-memory-grows))

### `[caches]`

- `mirror.enabled`, `.memory`, `.cpus`, `.ttl`: the Docker Hub mirror, its limits (`memory` counts in the budget) and how long it keeps an unused image
- `mirror.max_size` (default `"10G"`), `pnpm.max_size`, `maven.max_size`: emptied above this when no runner runs
- `reseed_at` (default `"2G"`): slot 1's layers become the profile's snapshot once they changed this much and it is idle ([Warm caches](../running/#warm-caches))
- `snapshot_max` (default `"10G"`): a larger snapshot starts over from the image
- `build.enabled` (default `true`): the shared [build cache](../running/#build-cache)
- `build.max_size` (default `"10G"`): above this its least recently used entries go when no runner runs; [GitHub Actions' cache](../running/#github-actions-cache) counts too
- `build.branches` (default `[]`): branches besides the default branch whose pushes, schedules and manual runs write to it
- `build.directory` (default `$XDG_CACHE_HOME/runnerd/build-cache`): its entries
- `build.actions_cache` (default `true`): it also serves GitHub Actions' cache in place of GitHub's

### `[profiles.<name>]`

- `image` or `image_stage`: exactly one ([Runner images](#runner-images))
- `cpus`, `memory`: each runner's CPU quota and memory limit ([Sharing the CPUs](../admission/#sharing-the-cpus))
- `slots`: the most runners at once
- `record_failures` (default `false`): keep failed jobs as [records](#records-of-failed-jobs)
- `min_memory`, `max_memory` (default unset): bounds for sizing advice and [auto sizing](../admission/#auto-sizing); unset, what its jobs need and `MemoryMax` holds
- `max_slots` (default unset): the most `slots` auto sizing raises to; unset, as many as `MemoryMax` holds, or under `measured` as leave each slot 2G of disk
- `priced_as` (default `actions_linux`): the GitHub-hosted runner its jobs are [priced at](../insights/#what-the-minutes-would-have-cost), by billing name, such as `linux_4_core`

### `[[repositories]]`

- `name`: `owner/name`; repeat the entry for [several profiles](#split-light-and-heavy-jobs)
- `profile`: the profile its jobs run on
- `labels`: at least one; a job runs here when all its `runs-on` labels are listed
- `warm` (default `1`): [warm runners](../running/#warm-runners) kept while active; `0` turns off
- `build_cache` (default `true`): its runners get the build cache
- `build_cache_writers` (default `"default-branch"`): whose jobs write to it: `"pull-requests"` adds [people's pull requests from its own branches](../running/#build-cache)

### `[history]`

- `database` (default `$XDG_STATE_HOME/runnerd/runnerd.db`): the [job history](../running/#job-history)'s file
- `samples` (default `"7d"`), `logs` (`"30d"`), `events` (`"30d"`, for `Last-Event-ID` resumes), `jobs` (`"90d"`): how long a job's samples, a finished job's log, events and a finished job are kept; totals and peaks outlive the samples
- `log_max` (default `"50M"`): the most log kept per job

### `[records]`

- `max_total` (default `"20G"`), `max_count` (`10`), `max_age` (`"7d"`): the disk all records may take (`runnerd doctor` warns at 80%), how many are kept, and for how long; the oldest go first
- `min_free` (default `"10G"`): the job gets no record if it would leave Docker less free disk than this

### `[sizing]`

- `margin` (default `15`): percent added to a sampled peak in [advice](../admission/#sizing) and predictions
- `min_jobs` (default `10`): the fewest runs before a peak becomes advice or a prediction
- `auto` (default `false`): runnerd sizes each profile's `memory`, `slots` and `cpus` itself (`runnerd init` writes `true`)
- `interval`, `raise_interval` (default `"1h"`): the least time between a change to a profile and one that lowers its `memory` or `cpus`, or that only raises; `raise_interval` is at most `interval`
- `max_step` (default `50`): the most percent one change lowers `memory` or moves `cpus`

### `[web]`

- `origins` (default `[]`): proxy addresses whose dashboard pages may write ([From another device](../clients/#from-another-device)): `https://host:port`, or `http` for loopback only
- `open` (default none): the one of `origins` that `runnerctl web` opens

### `[notify]`

[Notifications](../insights/#notifications) go nowhere without targets. `digest_at` (default `"09:00"`, host-local `HH:MM`) is when targets that list `digest` get it. Each `[[notify.targets]]`:

- `name`, `kind` (required): what logs and `runnerctl notify test` call it; `"ntfy"`, `"discord"` or `"webhook"`
- `url` (required): the topic or webhook URL; a redirect counts as a failed send
- `headers` (default `{}`): sent with each post, such as `{ Authorization = "Bearer tk_…" }`
- `events` (default `["failed", "lost", "runner", "insights"]`): what it is sent; add `"digest"`

`url` and header values are secrets: the dashboard, `runnerctl config show` and `GET /v1/config` show them as `"<secret>"`, and saving that text keeps the values. Write a new value to change one, and all values again after renaming a target. The file is mode 0600; `runnerd doctor` warns otherwise.
