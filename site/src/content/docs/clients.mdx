## Dashboard

`runnerd serve` serves it on `127.0.0.1:7477`; `--web <address>` picks another loopback address, `--web off` serves none. Each browser signs in once, through a one-time link the daemon keeps in `$XDG_RUNTIME_DIR/runnerd.web`:

```sh
runnerctl web
# without runnerctl
xdg-open "$(head -n 1 "$XDG_RUNTIME_DIR/runnerd.web")"
```

A browser stays signed in for 30 days after its last visit, across restarts of runnerd and of the browser. The session secret is in `dashboard-session` beside the job history (`~/.local/state/runnerd/`), readable by you only. The directory must be one other users cannot write. To sign every browser out, this one included, and end every link and QR code made before:

```sh
runnerctl web --sign-out-all
```

Pages update as things happen, over one server-sent event stream per page. Memory and CPU are sampled every 2 s, so a shorter peak does not show; the dashboard calls them sampled peaks.

Any local user can reach the port, so every page needs the session cookie a login link sets, and writes such as a pause also need the dashboard's own `Origin`, so another site the browser has open cannot send them. A link to a page from elsewhere, such as GitHub, a notification or the browser's history, opens it signed in. The pages load nothing from elsewhere: the Datastar script and the font are in the binary.

### From another device

The dashboard listens on loopback only. To open it on a phone or another computer, put a proxy that serves HTTPS in front of it, such as `tailscale serve`, which reaches every device on your tailnet:

```sh
tailscale serve --https 8443 http://127.0.0.1:7477
```

Then add the proxy's address to [`[web] origins`](../configuration/#web) in `runnerd.toml` and restart runnerd, so writes from its pages pass the `Origin` check:

```toml
[web]
origins = ["https://forge.tail0b5e.ts.net:8443"]
```

Now `runnerctl web` prints a one-time link for each address in `[web] origins` too, after opening the dashboard here. To sign a phone in, scan a QR code: open **Config** in the dashboard on this computer and choose **Show a QR code** under **Add a device**, or print one in the terminal:

```sh
runnerctl web --qr
```

If you always reach the dashboard through the proxy, even on this computer, name it in `open` too, and `runnerctl web` opens it there instead of on `127.0.0.1`, still printing the loopback link. `runnerctl web --local` opens the loopback address for one run:

```toml
[web]
origins = ["https://forge.tail0b5e.ts.net:8443"]
open = "https://forge.tail0b5e.ts.net:8443"
```

A QR code works once, within 5 minutes, and only on the address it shows; each one is new. A link from `runnerctl web` works once, and the daemon writes a new one in its place. Each address has its own link, so using one leaves the others working. `--base <origin>` prints the link for a proxy not in `[web] origins`, which can then only read. Behind a proxy that says it took the request over HTTPS (`X-Forwarded-Proto`, which `tailscale serve` sends), the session cookie is `Secure`. Anyone who can reach the proxy sees the sign-in page and nothing else without a link.

runnerd does not trust Tailscale's identity headers such as `Tailscale-User-Login`: any local user could send them straight to `127.0.0.1:7477`.

### Install it as an app

Chromium-based browsers (Chrome, Edge, Brave) install the dashboard as an app with its own window: on the desktop, the install button in the address bar or **Install** in the menu; on Android, **Add to home screen** in Chrome's menu, then **Install**. Both work through the HTTPS proxy and on `http://127.0.0.1:7477`, which browsers treat as secure. Each address installs as its own app. The app is the same live pages and needs runnerd running; nothing is kept for offline use. Firefox installs web apps on Windows only, so on Linux it stays a tab.

Views of the same thing are linked. On the overview, pointing at, focusing or tapping a slot's block, card, running job or repository lights up the others and says above the bar what the block holds, free space included; a slot's block opens its job. On a job, a step marks its stretch of the memory and CPU charts. On the history, a day, pointed at or stepped to with the arrow keys, is marked on all three charts and its numbers replace the 30 days' in the headline.

## runnerctl

It talks to the socket (`--socket` picks another), prints aligned text, coloured on a terminal unless `NO_COLOR` is set, and with `--json` prints the API's response unchanged.

```console wrap=false
$ runnerctl status
runnerd 0.0.12  23.5G of 33G reserved in runnerd.slice

PROFILE  SLOT  STATE  REPOSITORY          RUNNER                                    UP
jvm         1  busy   halyard/ledger      runnerd-3f9a-forge-jvm-1-1792814287   7m 11s
jvm         2  idle   halyard/ledger      runnerd-3f9a-forge-jvm-2-1792814114  10m 4s
node        1  busy   halyard/storefront  runnerd-3f9a-forge-node-1-1792814405  5m 13s
node        2  idle   halyard/storefront  runnerd-3f9a-forge-node-2-1792814702     16s

REPOSITORY          PROFILE  STATE   QUEUED  LABELS
halyard/ledger      jvm      active       0  self-hosted,linux,x64,jvm
halyard/storefront  node     active       4  self-hosted,linux,x64,node

JOB           REPOSITORY          WORKFLOW / NAME    QUEUED
120055991710  halyard/storefront  E2E / visual-diff  45s ago
120055991711  halyard/storefront  E2E / a11y         39s ago
120055991712  halyard/storefront  E2E / lighthouse   26s ago
120055991713  halyard/storefront  E2E / unit         13s ago
```

| Command | What it shows or does |
|---|---|
| `runnerctl status` | the memory budget, and the CPU budget under [CPU admission](../admission/#cpu-admission), every slot and its runner, the repositories and their queues |
| `runnerctl jobs [--repo halyard/ledger] [--failed] [--since 7d]` | jobs newest first: result, time waited and run, sampled memory peak; `--state`, `--conclusion`, `--before`, `--limit` too |
| `runnerctl job <id>` | one job: timeline, steps with their durations, CPU, memory, network and how often memory pressure throttled it, log size |
| `runnerctl logs <id> [-f]` | its log; `-f` follows it until the job's record is final, waiting out a daemon restart |
| `runnerctl tui` | a [full-screen dashboard](#runnerctl-tui) in the terminal |
| `runnerctl watch` | slots, running jobs with their current step and last sample, queued and finished jobs, redrawn as events arrive; one line per event when not on a terminal, one JSON event per line with `--json` |
| `runnerctl pause <repo> [--force]`, `resume <repo>` | the repository gets no new runners, also after a restart; refused while it runs a job, naming the job, unless `--force` cancels the job's run and removes its runner |
| `runnerctl pause --all [--force]`, `resume --all` | the same for every repository; refused while any runs a job, pausing none |
| `runnerctl reseed <profile>` | makes slot 1's layers the profile's snapshot once its slots are free, and waits for it (`--no-wait`) |
| `runnerctl shell <job> [--step 3]` | a shell in a failed job's [record](../running/#records-of-failed-jobs), in its workspace; exiting removes its container |
| `runnerctl records`, `records rm <job>` | the records of failed jobs with their sizes and limits; removes one, or `--all`, or those `--older-than 2d` |
| `runnerctl sizing [--since 7d]` | per profile and per job: percentiles and the largest of the sampled memory and CPU peaks, waits, how busy the slots were, and the [advice](../admission/#sizing) |
| `runnerctl sizing apply <profile> [--yes]` | writes a profile's advised `memory` and `slots` into the daemon's config after showing the change and asking; the daemon checks it against the budget first |
| `runnerctl sizing undo <profile> [--yes]` | writes back the `memory` and `slots` [auto sizing](../admission/#auto-sizing) last replaced, the same way; both refuse to write over a config changed since they read it |
| `runnerctl insights [--days 30]`, `insights --digest` | one line per [insight](../insights/), then each repository's waits this week against the last; or the last 24 hours |
| `runnerctl notify test [--target phone]` | sends each `[notify]` target a test message and says what each did; fails unless every one got it |
| `runnerctl caches [--clean <volume>]` | the cache volumes, their sizes and limits; or empties a slot layer or shared cache no job uses, stopping the runners that wait for one |
| `runnerctl config show`, `config check [file]` | the config the daemon runs with; a file checked against the daemon's budget, as `runnerd check-config` does |
| `runnerctl doctor` | the daemon's host checks, or `runnerd doctor` run here when the daemon is not running |
| `runnerctl web` | opens the dashboard with a one-time login link from `$XDG_RUNTIME_DIR/runnerd.web`, on `[web] open` if set, and prints one for each other address (`--local` opens the loopback address, `--base <origin>` a proxy's, `--no-open` prints them all, `--qr` shows a fresh 5-minute link on each origin as a QR code, `--sign-out-all` signs every browser out) |

`runnerctl sizing apply node` shows `memory = "7G" -> "2.5G"` and `slots = 2 -> 5` under `[profiles.node]` and asks before it writes. Without a terminal to ask on it needs `--yes`. The rest of the file, comments included, stays as written.

Under [auto sizing](../admission/#auto-sizing) the first line ends with `auto sizing applies it`, the `apply` hint goes, and each change shows under its profile:

```console wrap=false

  auto sizing 2d 3h ago: memory 7G → 5.25G, slots 2
  runnerctl sizing undo node
```

## runnerctl tui

The dashboard, for a host you reach over SSH. It shows what the web dashboard does, in the same words:

- a health line: slots running, jobs waiting and the oldest's wait, and over the last 24 hours the p95 wait with a bar for the longest wait of each hour, and the failures, then how many warning [insights](../insights/) hold;
- the budget as one bar, a block per slot as wide as its memory cap and filled as far as its job uses it, then the mirror and each seed container; its heading adds the CPU budget under [CPU admission](../admission/#cpu-admission);
- a card per slot with the job, its step, run time, and memory and CPU sparklines;
- **Waiting**: each queued job, oldest first, with how long it has waited and why runnerd has not started it;
- the repositories, the latest jobs, and the slice's memory and CPU up to its MemoryMax and CPUs;
- the history, filtered by outcome, repository and workflow;
- the records of failed jobs, with the command that opens a shell in each;
- sizing: each profile's peaks and advice, its jobs below, what auto sizing last changed and, while it is on, what its next look changes, how long a recent change holds a profile, or why no look changes anything;
- a job: its timeline and, while it waits, why; the same job's latest runs as bars of their run times, waits and memory peaks, with the median run and wait; its steps on one time axis, memory and CPU against its container's caps, and its log, followed while the job runs.

```sh
runnerctl tui
```

A wide terminal adds columns, and the charts take the rows the lists leave.

| Key | |
|---|---|
| `1` `2` `3` `4` | overview, history, records, sizing; `o` and `h` open the first two too |
| `tab`, `j` `k` (or arrows) | the overview's pane (slots, waiting, repositories, latest jobs); move in it, or scroll a log; `PgDn` `PgUp` move by ten |
| `enter`, `esc` | open the selected job; back |
| `p` `r` | pause or resume the selected repository; a pause refused while it runs a job asks before forcing it |
| `P` `U` | pause or resume every repository, asking the same way |
| `R` | reseed the selected slot's profile |
| `c` `s` `w` `]` `[` | history: cycle the outcome, repository and workflow filters, next and previous page |
| `d` `D` | records: remove the selected record, or all of them, after `y` |
| `a` | sizing: write the selected profile's advice into the config, after `y` |
| `G` `g` | follow the log, or go to its start |
| `?` `q` | all keys; quit. The footer shows the keys of the view, as many as fit |
| `ctrl-z` | suspend; `fg` brings it back, redrawn |

SIGINT, SIGTERM and SIGHUP quit and SIGTSTP suspends, each after giving the terminal back. When the daemon goes away the header says `reconnecting`. Once it is back, the event stream resumes after the last event read, and an open job's log carries on from its next line.

`cargo build -p runnerd-cli --no-default-features` builds `runnerctl` without the TUI.

Frames set in JetBrains Mono ([OFL](../fonts/JetBrainsMono-OFL.txt)).
