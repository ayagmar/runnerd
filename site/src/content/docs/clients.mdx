## Dashboard

`runnerd serve` serves it on `127.0.0.1:7477`; `--web <address>` picks another loopback address, `--web off` serves none. A browser signs in once through a one-time link the daemon keeps in `$XDG_RUNTIME_DIR/runnerd.web`:

```sh
runnerctl web
# without runnerctl
xdg-open "$(head -n 1 "$XDG_RUNTIME_DIR/runnerd.web")"
```

The browser stays signed in for 30 days after its last visit. `runnerctl web --sign-out-all` makes a new session secret (`dashboard-session` beside the job history), which signs every browser out and ends every earlier link and QR code. Writes such as a pause also need the dashboard's own `Origin`, so another site open in the browser cannot send them. Memory and CPU are sampled every 2 s, so a shorter peak does not show.

The navigation has five views: Overview, Jobs (History and Records), Insights, Capacity (Sizing and Caches) and Settings (Config).

| Page | Shows |
|---|---|
| Overview | slots running, jobs waiting, the p95 wait over 24 hours, failures (red only when a runner failed, not when a job's tests do); each waiting job with why it waits; the memory budget as a bar, hatched where the host or [measured admission](../admission/#measured-admission) closes it; a card per slot; the latest jobs; pause and resume per repository, which lasts across restarts |
| History | the last 30 days in charts, then every matching job; filters by repository, workflow and outcome combine and can be bookmarked; workflow and outcome filter the job list only, the charts use the repository filter |
| Records | the [records of failed jobs](../running/#records-of-failed-jobs) with size and age; remove one or all |
| Sizing | per profile, memory peaks against the cap, waits, how busy the slots were and the [advice](../admission/#sizing), which a button opens in the config editor, unsaved; what [auto sizing](../admission/#auto-sizing) changes next and has changed, with a link that opens the last change undone |
| Insights | a card per [insight](../insights/), warnings first; the last 24 hours; each repository's waits this week against the week before, warm and cold apart |
| Caches | each volume's size over 30 days; the build cache's 7-day hit rate and whether it serves [GitHub Actions' cache](../running/#github-actions-cache); reseed a snapshot or empty a cache |
| Config | `runnerd.toml` in an editor that checks it as you type against `MemoryMax` and saves only when it fits; **Add a device** shows a QR code |

### From another device

To open the dashboard on a phone or another computer, put an HTTPS proxy in front of it, such as `tailscale serve`:

```sh
tailscale serve --https 8443 http://127.0.0.1:7477
```

Add the proxy's address to [`[web] origins`](../configuration/#web) and restart runnerd, so writes from its pages pass the `Origin` check:

```toml
[web]
origins = ["https://forge.tail0b5e.ts.net:8443"]
open = "https://forge.tail0b5e.ts.net:8443"   # optional: runnerctl web opens this, not 127.0.0.1
```

`runnerctl web` now prints a link for each origin too. To sign a phone in, scan a QR code: **Show a QR code** under **Add a device** on the Config page, or `runnerctl web --qr`. A QR code works once, within 5 minutes; a link works once. `--base <origin>` prints a read-only link for a proxy not in `origins`, `--local` opens the loopback address once. Behind a proxy that sends `X-Forwarded-Proto` the session cookie is `Secure`. runnerd ignores Tailscale's identity headers, since any local user could send them to the port.

### Install as an app

Chromium browsers install the dashboard as an app: the install button in the address bar, or **Add to home screen** in Chrome on Android. It works through the proxy and on `http://127.0.0.1:7477`, one app per address. Firefox installs web apps on Windows only.

## runnerctl

`--socket` picks another socket; `--json` prints the API's response unchanged.

| Command | What it does |
|---|---|
| `status` | budgets, slots, repositories and queues, and why each queued job waits |
| `jobs [--repo R] [--failed] [--since 7d]` | jobs newest first; also `--state`, `--conclusion`, `--before` (next page), `--limit` |
| `job <id>`, `logs <id> [-f] [--from N]` | one job's timeline, steps and usage; its log, `-f` following it to the end |
| `tui`, `watch` | the [terminal dashboard](#terminal-dashboard); slots, running, queued and finished jobs redrawn as events arrive, or one line per event off a terminal |
| `pause <repo> [--force]`, `resume <repo>`, `pause --all`, `resume --all` | no new runners, also after a restart. Refused while a job runs; `--force` cancels its run and removes the runner |
| `cancel <job> [--confirm <token>] [--force]` | shows what cancelling the job's workflow run on GitHub stops (the whole run, at its current attempt, on every runner) and the command that sends it; `--confirm` sends what it showed; `--force` sends without showing it, for scripts |
| `rerun <job> [--failed] [--confirm <token>] [--force]` | shows what GitHub re-runs: this job and the jobs that depend on it, or with `--failed` the run's failed jobs; `--confirm` and `--force` as for `cancel` |
| `reseed <profile> [--no-wait]` | makes slot 1's layers the profile's snapshot once its slots are free |
| `shell <job> [--step N]` | a shell in a failed job's [record](../running/#records-of-failed-jobs); exiting removes the container |
| `records`, `records rm <job>` | the records with sizes and limits; remove one, `--all`, or `--older-than 2d` |
| `sizing [--since 30d]` | peak percentiles, waits, busy slots, the [advice](../admission/#sizing) and what [auto sizing](../admission/#auto-sizing) does next |
| `sizing apply <profile> [--yes]`, `sizing undo <profile>` | writes the advised `memory` and `slots`, or what auto sizing replaced (`cpus` too), into the config after showing the change |
| `insights [--days 14] [--digest]` | what the minutes [would have cost](../insights/#what-the-minutes-would-have-cost) on GitHub's runners and one line per [insight](../insights/); `--digest` the last 24 hours |
| `notify test [--target NAME]` | sends each `[notify]` target a test message |
| `caches [--clean <volume>]` | volumes, sizes, limits and build cache hits; or empties a volume no runner uses |
| `config show`, `config check [file]` | the config the daemon runs with; a file checked against its budget |
| `doctor` | the daemon's host checks, or `runnerd doctor` when no daemon runs |
| `web` | opens the dashboard with a one-time link ([above](#from-another-device)) |

### One job

The job tables have the columns Outcome, Job, Repository, Branch, Queued, Waited, Ran, Memory peak and CPU. `runnerctl job` ends with what the job used:

```console wrap=false
$ runnerctl job 120055991526
Usage
  Memory peak      6.61G
  Average memory   5.13G
  CPU peak         7.57 cores
  Average CPU      3.33 cores
  CPU time         37m 43s
  Received         506.45M
  Sent             56.27M
  From the mirror  168.82M
  CPU held back    held at its CPU cap in 5% of its busy time, waited for a CPU 25% of its run
  Build cache      30 of 36 lookups hit (83%), 101.29M served, 12.66M stored
  Log              54 lines, 2.15K  runnerctl logs 120055991526
  memory peaks are sampled every 2 s; spikes shorter than that do not show
```

`CPU held back` gives a share of the job's busy time, which reads higher than the share of the whole run that [auto sizing](../admission/#auto-sizing) counts.

### Cancel and re-run

GitHub cancels runs, not jobs, and a re-run takes the jobs that depend on the one re-run with it. So `runnerctl cancel` and `runnerctl rerun` first read the run from GitHub, print what GitHub would do to its current attempt and the other jobs of the run runnerd knows (GitHub may have more, on other runners), and send nothing. They end with a command such as `runnerctl cancel 9001 --confirm 3f9a…`, which sends what they showed, once, within 5 minutes. If the run has moved to another attempt by then, or runnerd's config changed, nothing is sent: you get a new preview. If GitHub would not show the run, there is nothing to confirm until it does. `--force` skips the preview and sends at once, for scripts. The answer is one of four: GitHub took it, the run had already finished, GitHub refused (with its HTTP status and what to check), or the outcome is unknown, as after a timeout; then check the run on GitHub before asking again. runnerd's own record of the job stays as it was; the cancelled job and the new attempt arrive as GitHub lists them. [`[github] job_actions = false`](../configuration/#github) turns both off.

### Sizing

```console wrap=false
$ runnerctl sizing
[...]
node  7G × 2, 8 CPUs; 242 jobs, slots busy 78%, waited p50 12s p95 4m 20s
  warm runners took 187 of 242 jobs: waited p50 2s, the others 21s
  memory p50 1.4G p95 1.9G p99 2G max 2.1G of 242 recent runs
  cpu    p50 3.1 p95 6.9 p99 7.6 max 7.9 of the 242 at 8 CPUs
  lower memory to 3.25G from 7G, its largest peak + 1G for page cache; 4 slots fit in the same 14G
  Next look, within 5 minutes: memory 7G → 5.25G, slots 2

  REPOSITORY          JOB         RUNS   P50   P95  P99   MAX  CPU P99  WAIT P95  NEEDS
  halyard/storefront  CI / build   236  1.4G  1.9G   2G  2.1G      7.6    4m 20s  3.25G
  halyard/storefront  CI / e2e       6  1.8G    2G   2G    2G      7.6    4m 40s  max 2G
```

Peaks cover each job's recent runs, CPU peaks only runs at the profile's current `cpus`. The demo runs auto sizing with `interval = "3d"` and `max_step = 25` ([`[sizing]`](../configuration/#sizing)). With auto sizing off, a profile the advice would change ends with `runnerctl sizing apply node`, which shows `memory = "7G" -> "3.25G"` under `[profiles.node]` and asks before writing; without a terminal it needs `--yes`. The rest of the file stays as written.

## Terminal dashboard

`runnerctl tui` shows the web pages' figures in the same words, for a host you reach over SSH. Its views, `1` to `5`, are Overview, Jobs, Insights, Capacity and Settings; pressing a view's digit again opens its next section, so `2` `2` goes from History to Records and `4` `4` from Sizing to Caches. The overview lists what needs attention, then a row per slot. `enter` opens a job: on a failed one the failure first, then its timeline, steps, memory and CPU against the caps, latest runs, and the log, folded by step and followed while the job runs.

| Key | |
|---|---|
| `1` to `5` | overview, jobs, insights, capacity, settings; again for the view's next section; `o` and `h` open the overview and history too |
| `tab`, `j` `k` or arrows, `PgDn` `PgUp` | the overview's pane; move in it, or in a log; by ten |
| `enter`, `esc` | open the selected job, or where an attention item points; back |
| `!` | what needs attention; the header's count opens it too |
| `/`, `n` `N` | jobs: search names, workflows and branches; job: search the log, the next and previous match |
| `f` `s` `t`, `l`, `x` | jobs: pick a filter, the order, the time range; the slots' timeline; clear the filters |
| `]` `[` | jobs: next and previous page |
| `enter`, `G` `g` | job: fold or open a step or group; follow the log, or go to its start |
| `c` | job: compare with an earlier run of the same job |
| `x`, `a` `A` | job: cancel its run, re-run it, re-run the run's failed jobs; each shows what GitHub would do and sends only on `y` |
| `p` `r`, `P` `U` | pause or resume the selected repository, or every one; a pause refused while a job runs asks before forcing it |
| `R` | reseed the selected slot's profile |
| `d` `D` | records: remove the selected record, or all, after `y`; caches: empty the selected volume, after `y` |
| `a` | sizing: write the selected profile's advice into the config, after `y` |
| `u` | settings: read the config and the doctor's checks again |
| click, wheel | select, click again to open; scroll. `--no-mouse` or `RUNNERCTL_NO_MOUSE=1` leaves the mouse to the terminal |
| `?`, `q` or `ctrl-c` | all keys; quit |
| `ctrl-z` | suspend; `fg` brings it back |

A daemon too old for a view's read says so in the view, `not supported by this runnerd`, rather than showing it empty.

When the daemon goes away the header says `reconnecting` and the event stream resumes where it stopped. `cargo build -p runnerd-cli --no-default-features` builds `runnerctl` without the TUI.
