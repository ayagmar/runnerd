Both are on `main`, for the next release; 0.0.1's `runnerctl` has no commands yet. They talk to the daemon only. The output and screenshots here come from the dashboard's demo daemon, whose made-up machine is the [example config](../configuration/).

## Dashboard

`runnerd serve` serves it on `127.0.0.1:7477`; `--web <address>` picks another loopback address, `--web off` serves none. Each browser logs in once, through a one-time URL the daemon keeps in `$XDG_RUNTIME_DIR/runnerd.web`:

```sh
runnerctl web
# without runnerctl
xdg-open "$(cat "$XDG_RUNTIME_DIR/runnerd.web")"
```

Pages update as things happen. Memory and CPU are sampled every 2 s, so a shorter peak does not show.

## runnerctl

It talks to the socket (`--socket` picks another), prints aligned text, coloured on a terminal unless `NO_COLOR` is set, and with `--json` prints the API's response unchanged.

```console wrap=false
$ runnerctl status
runnerd 0.0.1  24G of 33G reserved in ci.slice

PROFILE  SLOT  STATE  REPOSITORY          RUNNER                                    UP
jvm         1  busy   halyard/ledger      runnerd-3f9a-forge-jvm-1-1792706088   7m 13s
jvm         2  free
node        1  busy   halyard/storefront  runnerd-3f9a-forge-node-1-1792706206  5m 15s
node        2  idle   halyard/storefront  runnerd-3f9a-forge-node-2-1792706503     18s

REPOSITORY          PROFILE  STATE   QUEUED  LABELS
halyard/ledger      jvm      active       0  self-hosted,linux,x64,jvm
halyard/storefront  node     active       1  self-hosted,linux,x64,node
```

| Command | What it shows or does |
|---|---|
| `runnerctl status` | the memory budget, every slot and its runner, the repositories and their queues |
| `runnerctl jobs [--repo halyard/ledger] [--failed] [--since 7d]` | jobs newest first: result, time waited and run, sampled memory peak; `--state`, `--conclusion`, `--before`, `--limit` too |
| `runnerctl job <id>` | one job: timeline, steps with their durations, CPU, memory, network, log size |
| `runnerctl logs <id> [-f]` | its log; `-f` follows it until the job's record is final |
| `runnerctl watch` | slots, running jobs with their current step and last sample, queued and finished jobs, redrawn as events arrive; one line per event when not on a terminal, one JSON event per line with `--json` |
| `runnerctl pause <repo> [--force]`, `resume <repo>` | the repository gets no new runners; refused while it runs a job, unless `--force` cancels the job's run and removes its runner |
| `runnerctl reseed <profile>` | makes slot 1's layers the profile's snapshot once its slots are free, and waits for it (`--no-wait`) |
| `runnerctl caches [--clean <volume>]` | the cache volumes, their sizes and limits; or empties a slot layer or shared cache no runner uses |
| `runnerctl config show`, `config check [file]` | the config the daemon runs with; a file checked against the daemon's budget, as `runnerd check-config` does |
| `runnerctl doctor` | the daemon's host checks, or `runnerd doctor` run here when the daemon is not running |
| `runnerctl web` | opens the dashboard with the one-time login URL (`--no-open` prints it) |

### A pause while a job runs

```console
$ runnerctl pause halyard/ledger
error: halyard/ledger runs job 120055991700 on runnerd-3f9a-forge-jvm-1-1792706088; pause with force to cancel it
`runnerctl pause --force halyard/ledger` cancels its runs and removes their runners
```
