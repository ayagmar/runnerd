## Dashboard

`runnerd serve` serves it on `127.0.0.1:7477`; `--web <address>` picks another loopback address, `--web off` serves none. Each browser logs in once, through a one-time URL the daemon keeps in `$XDG_RUNTIME_DIR/runnerd.web`:

```sh
runnerctl web
# without runnerctl
xdg-open "$(cat "$XDG_RUNTIME_DIR/runnerd.web")"
```

Pages update as things happen. Memory and CPU are sampled every 2 s, so a shorter peak does not show.

## runnerctl

It talks to the socket (`--socket` picks another), prints aligned text, coloured on a terminal unless `NO_COLOR` is set, and with `--json` prints the API's response unchanged. Sizes of 10 or more round to whole units, so the demo's 23.5G reads 24G.

```console wrap=false
$ runnerctl status
runnerd 0.0.5  24G of 33G reserved in ci.slice

PROFILE  SLOT  STATE  REPOSITORY          RUNNER                                    UP
jvm         1  busy   halyard/ledger      runnerd-3f9a-forge-jvm-1-1792708105    7m 9s
jvm         2  free
node        1  busy   halyard/storefront  runnerd-3f9a-forge-node-1-1792708223  5m 11s
node        2  idle   halyard/storefront  runnerd-3f9a-forge-node-2-1792708520     14s

REPOSITORY          PROFILE  STATE   QUEUED  LABELS
halyard/ledger      jvm      active       0  self-hosted,linux,x64,jvm
halyard/storefront  node     active       1  self-hosted,linux,x64,node
```

| Command | What it shows or does |
|---|---|
| `runnerctl status` | the memory budget, every slot and its runner, the repositories and their queues |
| `runnerctl jobs [--repo halyard/ledger] [--failed] [--since 7d]` | jobs newest first: result, time waited and run, sampled memory peak; `--state`, `--conclusion`, `--before`, `--limit` too |
| `runnerctl job <id>` | one job: timeline, steps with their durations, CPU, memory, network, log size |
| `runnerctl logs <id> [-f]` | its log; `-f` follows it until the job's record is final |
| `runnerctl tui` | a [full-screen dashboard](#runnerctl-tui) in the terminal |
| `runnerctl watch` | slots, running jobs with their current step and last sample, queued and finished jobs, redrawn as events arrive; one line per event when not on a terminal, one JSON event per line with `--json` |
| `runnerctl pause <repo> [--force]`, `resume <repo>` | the repository gets no new runners, also after a restart; refused while it runs a job, unless `--force` cancels the job's run and removes its runner |
| `runnerctl pause --all [--force]`, `resume --all` | the same for every repository; refused while any runs a job, pausing none |
| `runnerctl reseed <profile>` | makes slot 1's layers the profile's snapshot once its slots are free, and waits for it (`--no-wait`) |
| `runnerctl caches [--clean <volume>]` | the cache volumes, their sizes and limits; or empties a slot layer or shared cache no runner uses |
| `runnerctl config show`, `config check [file]` | the config the daemon runs with; a file checked against the daemon's budget, as `runnerd check-config` does |
| `runnerctl doctor` | the daemon's host checks, or `runnerd doctor` run here when the daemon is not running |
| `runnerctl web` | opens the dashboard with the one-time login URL (`--no-open` prints it) |

## runnerctl tui

The dashboard, for a host you reach over SSH.

```sh
runnerctl tui
```

<Tui
  name="overview-96"
  label="The overview at 96 by 26: the budget bar with jvm slot 1 at 4.3G and node slot 1 at 2.7G used, one line per slot, the slice's memory and CPU charts, the repositories and the latest jobs."
/>

Profiles take the dashboard's colours in config order. `NO_COLOR` leaves bold, dim and block glyphs. On a narrow terminal, as here, the slots become one line each; at 80×24 the charts drop out first.

<Tui
  name="job"
  label="halyard/ledger's build job at 120 by 30: waited 4s, started in 5s, nine steps on one time axis with integration tests running, memory and CPU against the 9.0G and 8-core caps, and the log, followed."
/>

| Key | |
|---|---|
| `1` `2` | overview, history |
| `tab`, `j` `k` (or arrows) | the overview's pane (slots, repositories, latest jobs); move in it, or scroll a log |
| `enter`, `esc` | open the selected job; back |
| `p` `r` | pause or resume the selected repository; a pause refused while it runs a job asks before forcing it |
| `P` `U` | pause or resume every repository, asking the same way |
| `R` | reseed the selected slot's profile |
| `c` `s` `]` `[` | history: cycle the outcome and repository filters, next and previous page |
| `G` `g` | follow the log, or go to its start |
| `?` `q` | all keys; quit |
| `ctrl-z` | suspend; `fg` brings it back, redrawn |

When the daemon goes away the header says `reconnecting`, and the TUI picks up where it left off once it is back.

Frames set in JetBrains Mono ([OFL](../fonts/JetBrainsMono-OFL.txt)).
