## Dashboard

`runnerd serve` serves it on `127.0.0.1:7477`; `--web <address>` picks another loopback address, `--web off` serves none. Each browser logs in once, through a one-time URL the daemon keeps in `$XDG_RUNTIME_DIR/runnerd.web`:

```sh
runnerctl web
# without runnerctl
xdg-open "$(cat "$XDG_RUNTIME_DIR/runnerd.web")"
```

Pages update as things happen, over one server-sent event stream per page. Memory and CPU are sampled every 2 s, so a shorter peak does not show; the dashboard calls them sampled peaks.

Any local user can reach the port, so every page needs the session cookie the login URL sets, and writes such as a pause also need the dashboard's own `Origin`, so another site the browser has open cannot send them. The pages load nothing from elsewhere: the Datastar script and the font are in the binary.

Views of the same thing are linked. On the overview, pointing at, focusing or tapping a slot's block, card, running job or repository lights up the others and says above the bar what the block holds, free space included; a slot's block opens its job. On a job, a step marks its stretch of the memory and CPU charts. On the history, a day, pointed at or stepped to with the arrow keys, is marked on all three charts and its numbers replace the 30 days' in the headline.

## runnerctl

It talks to the socket (`--socket` picks another), prints aligned text, coloured on a terminal unless `NO_COLOR` is set, and with `--json` prints the API's response unchanged.

```console wrap=false
$ runnerctl status
runnerd 0.0.6  23.5G of 33G reserved in runnerd.slice

PROFILE  SLOT  STATE  REPOSITORY          RUNNER                                    UP
jvm         1  busy   halyard/ledger      runnerd-3f9a-forge-jvm-1-1792741296   7m 12s
jvm         2  free
node        1  busy   halyard/storefront  runnerd-3f9a-forge-node-1-1792741414  5m 14s
node        2  idle   halyard/storefront  runnerd-3f9a-forge-node-2-1792741711     17s

REPOSITORY          PROFILE  STATE   QUEUED  LABELS
halyard/ledger      jvm      active       0  self-hosted,linux,x64,jvm
halyard/storefront  node     active       1  self-hosted,linux,x64,node

JOB           REPOSITORY          WORKFLOW / NAME    QUEUED
120055991710  halyard/storefront  E2E / visual-diff  46s ago
```

| Command | What it shows or does |
|---|---|
| `runnerctl status` | the memory budget, every slot and its runner, the repositories and their queues |
| `runnerctl jobs [--repo halyard/ledger] [--failed] [--since 7d]` | jobs newest first: result, time waited and run, sampled memory peak; `--state`, `--conclusion`, `--before`, `--limit` too |
| `runnerctl job <id>` | one job: timeline, steps with their durations, CPU, memory, network, log size |
| `runnerctl logs <id> [-f]` | its log; `-f` follows it until the job's record is final, waiting out a daemon restart |
| `runnerctl tui` | a [full-screen dashboard](#runnerctl-tui) in the terminal |
| `runnerctl watch` | slots, running jobs with their current step and last sample, queued and finished jobs, redrawn as events arrive; one line per event when not on a terminal, one JSON event per line with `--json` |
| `runnerctl pause <repo> [--force]`, `resume <repo>` | the repository gets no new runners, also after a restart; refused while it runs a job, naming the job, unless `--force` cancels the job's run and removes its runner |
| `runnerctl pause --all [--force]`, `resume --all` | the same for every repository; refused while any runs a job, pausing none |
| `runnerctl reseed <profile>` | makes slot 1's layers the profile's snapshot once its slots are free, and waits for it (`--no-wait`) |
| `runnerctl shell <job> [--step 3]` | a shell in a failed job's [record](../running/#records-of-failed-jobs), in its workspace; exiting removes its container |
| `runnerctl records`, `records rm <job>` | the records of failed jobs with their sizes and limits; removes one, or `--all`, or those `--older-than 2d` |
| `runnerctl caches [--clean <volume>]` | the cache volumes, their sizes and limits; or empties a slot layer or shared cache no runner uses |
| `runnerctl config show`, `config check [file]` | the config the daemon runs with; a file checked against the daemon's budget, as `runnerd check-config` does |
| `runnerctl doctor` | the daemon's host checks, or `runnerd doctor` run here when the daemon is not running |
| `runnerctl web` | opens the dashboard with the one-time login URL from `$XDG_RUNTIME_DIR/runnerd.web` (`--no-open` prints it) |

### A pause while a job runs

```console
$ runnerctl pause halyard/ledger
error: halyard/ledger runs job 120055991700 on runnerd-3f9a-forge-jvm-1-1792741296
`runnerctl pause --force halyard/ledger` cancels its run and removes its runner
```

### Every repository at once

```console wrap=false
$ runnerctl pause --all
```

## runnerctl tui

The dashboard, for a host you reach over SSH. It shows what the web dashboard does:

- the budget as one bar, a block per slot as wide as its memory cap and filled as far as its job uses it, then the mirror and each seed container;
- a card per slot with the job, its step, run time, and memory and CPU sparklines;
- the slice's memory and CPU, the repositories, and the queued and latest jobs;
- the history, filtered by outcome and repository;
- the records of failed jobs, with the command that opens a shell in each;
- a job: its timeline, its steps on one time axis, memory and CPU against its container's caps, and its log, followed while the job runs.

```sh
runnerctl tui
```

  name="job"

| Key | |
|---|---|
| `1` `2` `3` | overview, history, records |
| `tab`, `j` `k` (or arrows) | the overview's pane (slots, repositories, latest jobs); move in it, or scroll a log |
| `enter`, `esc` | open the selected job; back |
| `p` `r` | pause or resume the selected repository; a pause refused while it runs a job asks before forcing it |
| `P` `U` | pause or resume every repository, asking the same way |
| `R` | reseed the selected slot's profile |
| `c` `s` `]` `[` | history: cycle the outcome and repository filters, next and previous page |
| `d` `D` | records: remove the selected record, or all of them, after `y` |
| `G` `g` | follow the log, or go to its start |
| `?` `q` | all keys; quit |
| `ctrl-z` | suspend; `fg` brings it back, redrawn |

SIGINT, SIGTERM and SIGHUP quit and SIGTSTP suspends, each after giving the terminal back. When the daemon goes away the header says `reconnecting`. Once it is back, the event stream resumes after the last event read, and an open job's log carries on from its next line.

`cargo build -p runnerd-cli --no-default-features` builds `runnerctl` without the TUI.

Frames set in JetBrains Mono ([OFL](../fonts/JetBrainsMono-OFL.txt)).
